## 三、这次部署的完整过程（含踩过的坑）

按时间顺序，坑也是资产，下次别再掉进去。

### 3.1 前置：买机器 + 域名
- 轻量应用服务器：地域选**中国香港**（选内地就要备案）、Ubuntu 22.04、2核2G、自定义密码
- 域名：`wenxingstar.top`，买完**必须做实名认证**（腾讯云限期内不做，解析会被暂停）

### 3.2 域名解析
在 **云解析 DNS → 记录管理** 加两条 A 记录（注意：不是「DNS 服务商信息」那个页面，那个页面只能改 NS）：

| 主机记录 | 类型 | 记录值 | TTL |
|---|---|---|---|
| `@` | A | `101.33.127.226` | 600 |
| `www` | A | `101.33.127.226` | 600 |

验证方法（在你自己电脑 cmd 里）：`ping wenxingstar.top`，能回 `101.33.127.226` 就对了。

### 3.3 安全组放行
云控制台 → 防火墙 → 放行 **80** 和 **443**。
> 80 是给 Let's Encrypt 验证证书用的，签完证书日常只用 443，但 80 不能关。

### 3.4 代码怎么上服务器（★ 这里踩大坑）

**原本想用 GitHub 中转，失败了**，原因：
- 本机代理没起来时，git 报 `Failed to connect to github.com:443 over proxy 127.0.0.1`
- 逐个测了 18 个端口，**本机没有任何可用代理**
- 不开代理直连 GitHub，21 秒超时（GitHub 在国内网络下不稳定）

**最终方案：用系统自带的 `scp` 直传**，绕开 GitHub。

```bat
:: 在你自己电脑的 cmd 里执行（先切到项目根目录的上一级）
cd /d "D:\MyConfiguration\jing.wang1\WorkBuddy\2026-09-23-20-52-42"
scp wenxing-src.zip ubuntu@101.33.127.226:/tmp/
```

**这里又踩一坑：密码不对。**
- 平时在网页终端是「免密连接（TAT）」，从没用过真正的密码
- scp 走的是另一套密码认证，输完直接 `Connection closed by 101.33.127.226 port 22`
- 解决：控制台 → 实例 → **更多 → 重置密码** → 重启实例 → 用新密码重传

> 判断技巧：`Connection closed` = 密码错；`Permission denied (publickey)` = 服务器只允许密钥登录，那种情况就别折腾密码了。

### 3.5 服务器上执行部署

网页终端登录（**免密连接 TAT**）后：

```bash
sudo -i
```
> 这台机器 `sudo` **免密**，回车就直接变 root，**不会问密码**，别以为卡住了。
> 判断是否成功：提示符从 `ubuntu@VM-0-5-ubuntu:~$` 变成 `root@VM-0-5-ubuntu:~#`（`$` → `#`）。

```bash
apt update && apt install -y unzip
unzip -o /tmp/wenxing-src.zip -d /opt/wenxing
cd /opt/wenxing && bash deploy/setup.sh wenxingstar.top
```

**这里第三个坑**：网页终端会话会掉回 `ubuntu@...$`，此时解压会报一堆
`checkdir error: cannot create /opt/wenxing/... Permission denied`。
**牢记：每次重新打开网页终端，都要先 `sudo -i`。**

### 3.6 部署脚本干了什么

`deploy/setup.sh` 是幂等的（可重复跑），依次做 6 件事：

1. 装系统依赖（curl / git / gnupg）
2. 装 Node.js 20（NodeSource 源）
3. 装 Caddy（cloudsmith 源）
4. 写 `ai-proxy/.env`（权限 600），已有 AI_KEY 则保留不动
5. 注册 systemd 服务 `wenxing`，设开机自启
6. 写 `/etc/caddy/Caddyfile` 并申请 HTTPS 证书

> 脚本会**先探测 `www.域名` 有没有解析**，解析到才纳入证书。没解析就只签主域名——否则 www 验证失败会拖住整个证书签发。

## 四、日常运维（照着抄命令）

### 4.1 更新线上代码（改了代码之后）

`/opt/wenxing` **已经是 git 检出**（不再是解压进去的），所以改完代码的固定流程是：**本机 push 到 GitHub → 服务器拉取 → 重启服务**。

**① 本机推上去**（在 tarot-h5 目录）
```bash
GIT_TERMINAL_PROMPT=0 git -c http.proxy=socks5h://127.0.0.1:1080 -c https.proxy=socks5h://127.0.0.1:1080 push origin main
```
> 必须走代理（Linsoc，SOCKS5，端口 1080）；凭据由 Windows 凭据管理器里的 token 自动提供，不用手输。

**② 腾讯云网页终端里拉取 + 重启**
```bash
sudo -i
cd /opt/wenxing && git fetch origin && git reset --hard origin/main && systemctl restart wenxing
```

> **为什么用 `git reset --hard origin/main` 而不是 `git pull`**：这台机器的 `main` 分支**没有设置 upstream 跟踪**，`git pull` 会直接报
> `There is no tracking information for the current branch.` 然后什么都不做——但因为命令链是 `&&`，重启也被一起跳过了，服务还是旧代码，很容易误判成"已经更新了"。
> 想以后能用 `git pull`，先执行一次 `git branch --set-upstream-to=origin/main main`。
> `reset --hard` 只覆盖 Git 跟踪的文件，`ai-proxy/.env`（真实密钥）被 gitignore 保护，不会被动。

**③ 确认真的生效**
```bash
git -C /opt/wenxing log --oneline -1     # 应显示本机最新那条提交
systemctl is-active wenxing              # 应输出 active
```

刷新页面就能看到新版本。**前端文件（js/css）可能有浏览器缓存，电脑 Ctrl+F5、手机换无痕窗口**。
> 微信里打开还有一层 X5 内核缓存，必要时换浏览器或等几分钟。

**④ 万一 GitHub 推不上去**（代理或网络问题），退回老办法：本机打 zip → scp → 网页终端解压覆盖
```bat
cd /d "D:\MyConfiguration\jing.wang1\WorkBuddy\2026-09-23-20-52-42\tarot-h5"
"C:\Windows\System32\tar.exe" -a -c -f ..\wenxing-src.zip --exclude=.git .
scp ..\wenxing-src.zip ubuntu@101.33.127.226:/tmp/
```
```bash
sudo -i
unzip -o /tmp/wenxing-src.zip -d /opt/wenxing
systemctl restart wenxing
```

### 4.2 常用命令

| 要做的事 | 命令 |
|---|---|
| 看实时日志 | `journalctl -u wenxing -f` |
| 看最近 50 行日志 | `journalctl -u wenxing -n 50 --no-pager` |
| 重启应用 | `systemctl restart wenxing` |
| 看服务是否在跑 | `systemctl status wenxing` |
| 本机自检接口 | `curl http://127.0.0.1:8787/health` |

| 看 Caddy 配置 | `cat /etc/caddy/Caddyfile` |
| 重启 Caddy | `systemctl restart caddy` |

## 五、故障排查表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 网页完全打不开 | 服务挂了 / 证书过期 | `systemctl status wenxing`；`journalctl -u caddy -n 50` |
| 打不开且浏览器提示「不安全」 | 证书没签出来 | 检查 80 端口是否放行、域名是否解析到本机 |
| `/health` 返回 `key:false` | AI 密钥没读到 | 看 `/opt/wenxing/ai-proxy/.env` 里 `AI_KEY=` 是否有值 |
| AI 解读一直转圈后报「已切换本地解读」 | 上游模型接口不通 / 密钥失效 | 看日志 `journalctl -u wenxing -n 50`，找 `[ai-proxy]` 开头的报错 |
| AI 返回的是「离线示例」 | 同上，走了兜底文案 | 同上；页面不会崩，只是文案变成本地规则生成 |
| 命令全报 `Permission denied` | 当前不是 root | 先 `sudo -i`，确认提示符是 `#` 不是 `$` |
| `scp` 报 `Connection closed` | 密码不对 | 控制台「更多 → 重置密码」后重启 |
| `git pull` 报 `There is no tracking information for the current branch` | 服务器上的 `main` 没设 upstream | 用 `git fetch origin && git reset --hard origin/main`，或先 `git branch --set-upstream-to=origin/main main`。**注意：这条报错会让后面的 `&& systemctl restart` 一起跳过，服务仍是旧代码** |
| 代码改了线上没变化 | ① push 没成功 ② 服务器没 pull ③ 缓存 | 依次查：本机 `git log -1` / 服务器 `git -C /opt/wenxing log --oneline -1` 两边 hash 是否一致；一致就强刷页面（Ctrl+F5） |
| `scp` 报 `Connection timed out` | 网络封了 22 端口 | 换网络（手机热点）再试 |
| 改了代码但页面没变 | 没覆盖 / 没重启 / 浏览器缓存 | 重跑 4.1 三步 + 强制刷新 |
| 微信里又打不开了 | 内容层面被风控（跟平台拦截不同） | 先确认手机浏览器能开；不能开查服务器，能开再查内容 |

## 六、备份与恢复

**要备份的只有三样：**
1. 代码 → 你自己电脑上的项目目录（`tarot-h5/`）就是主副本
2. AI 密钥 → `/opt/wenxing/ai-proxy/.env`（建议另外存一份到密码管理器）
3. 用户数据 → **不存在服务器上**。所有占卜记录、命盘历史都存在用户自己手机的 localStorage 里，服务器不存任何用户数据

**恢复方式**：机器重装也不怕，按第三节从 3.5 开始重跑一遍即可，10 分钟恢复。

**建议**：腾讯云控制台给实例开「快照」策略，改坏了可以一键回滚（几块钱一个月，值得）。

## 八、许可与合规

- **塔罗牌面**：Rider-Waite 1909（Pamela Colman Smith），**公有领域**
- **`js/vendor/mingyu-bazi.js`**：**AGPL-3.0-only**（来自 `mingyu-core@0.4.2`）。因为通过网络提供服务，AGPL 要求**向使用者提供对应源码**，所以页脚保留了源码入口（配置在 `index.html` 的 `window.WX_SOURCE_URL`）
- **`build/mingyu/`** 目录是构建现场，属于「对应源码」的一部分，**不能删**
- **数据红线**：生辰只在浏览器本地计算，**不上传**；AI 接口只接收结构化命盘（干支/五行/十神/星曜），payload 里严禁出现姓名、原始日期、年份
- **页面口径**：全站统一「娱乐参考 · 不预测不诊断」，AI 解读被明确要求**不下吉凶判断**
